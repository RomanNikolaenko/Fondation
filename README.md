# Fond

Десктопний торговий помічник для swing-трейдингу американських акцій: щодня
проводить аналіз наприкінці сесії (New York), формує сигнали входу, перевіряє
новини і звіти, створює наміри на схвалення й надсилає ордери в
Alpaca (paper або real). Архітектура «два процеси»: фоновий engine на Rust
(стан, розклад, ризик-контроль, локальний HTTP + WebSocket) і Tauri-застосунок
з інтерфейсом Angular, який дає огляд, схвалення, журнал, бектест і налаштування.

> Це особистий інструмент, а не фінансова порада. Гарантій прибутку немає;
> обовʼязково починайте на paper-акаунті.

## Склад репозиторію

| Частина                  | Що це                                                                      |
| ------------------------ | -------------------------------------------------------------------------- |
| `crates/fond-core`       | доменні типи: бари, сигнали, наміри, конфігурація, розклад (ET/Київ)       |
| `crates/fond-strategies` | стратегії: `trend_pullback`, `breakout` і ринковий фільтр                  |
| `crates/fond-backtest`   | бек-тест на історичних барах: витрати, частки, розділення in/out-of-sample |
| `crates/fond-adapters`   | брокер і дані: Alpaca та Finnhub, сканер юніверсу                          |
| `crates/fond-store`      | SQLite-сховище барав, подій, позицій і журналів                            |
| `crates/fond-api`        | REST/WS API над рушем (axum), DTO й генерація TypeScript типів             |
| `crates/fond-engine`     | цикл рушія, розклад, ризик-ліміти, замки та події                          |
| `apps/desktop`           | застосунок Tauri (Angular) і sidecar-запуск `fond-engine`                  |
| `docs/superpowers/plans` | реалізаційні плани; `docs/acceptance/part1.md` — чекліст приймання         |

## Швидкий стартВимоги: Node 24+, pnpm 12, Rust (stable, Windows: MSVC). Windows — основна ціль.

```powershell
pnpm install
cargo build -p fond-engine          # бінарник рушія для dev-режиму
pnpm --filter desktop tauri dev     # застосунок + рушій поруч
```

## Як це працює

1. **Сесія та розклад (ET).** Аналіз сигналів — наприкінці дня (за замовчуванням
   07:30 ET), дедлайн схвалення 08:55 ET, вікно надсилання ордерів 09:31–09:55 ET.
   Усі моменти розраховуються з урахуванням переходу зими/літа; в інтерфейсі
   поруч підказується київський час.
2. **Наміри та схвалення.** Стратегії пропонують сигнали; фільтри новин
   (Anthropic) і звітів можуть відхилити або позначити «обережно». Режим
   виконання — «з підтвердженням» (за замовчуванням) чи «авто» (з явним попередженням).
3. **Ризик.** ліміти на угоду, відкриті позиції, сектор, експозицію, денний
   і тижневий збиток. Тижневий ліміт у режимі «авто» знімається вручну.
4. **Журнал.** кожен крок (scan → signal → filter → risk → intent → order →
   fill → reconcile) пишеться в журнал з часом UTC і Києва, експортується в CSV.
5. **Клієнтські ідентифікатори.** ордери формуються з детермінованих
   `client_order_id`, тому перезапуск рушія під час відправлення не створює дублікатів.
6. **Аварійний стоп.** з UI можна зупинити рушій, за потреби — із відкликанням
   відкритих ордерів.
7. **Бек-тест.** частки стратегій ≤ 100%, розділення навчальний/перевірочний,
   витрати (прослизання + комісії); крива капіталу проти SPY і перелік
   обмежень оцінки (survivorship bias тощо).

## Секрети

Ключі зберігаються в системному ключнику (`keyring`), видимі значення
інтерфейс не показує — лише бейдж «збережено / немає»: `alpaca_key_id`,
`alpaca_secret`, `anthropic_api_key`, `finnhub_api_key`.
