# Специфікація: AI-аналітик як джерело сигналів (частина 2)

Дата: 2026-11-09. Статус: чернетка, направление погоджене.

## Мета

Claude періодично самостійно аналізує тікери юніверсу (бари, індикатори, новини,
поточні позиції) і **сам пропонує купівлі/продажі**. Пропозиції проходять той самий
конвеєр, що й технічні сигнали: ризик-менеджер → намір → схвалення/авто → ордери
на Alpaca. Людина бачить у UI екран «AI-аналіз» і затверджує (або авто-режим).

## Принципи

1. **AI пропонує, конвеєр вирішує.** Пропозиція AI перетворюється на
   `EntrySignal`/`ExitDecision` з `StrategyId("ai")` і далі йде через існуючі
   ризик-ліміти та схвалення. Жодних ордерів повз конвеєр.
2. **Окремий джоб за розкладом**, а не переробка `Strategy::evaluate_entry`
   (синхронна чиста функція). Технічні стратегії не змінюються.
3. **Новини AI вже бачив сам** — повторний виклик LLM для новинного фільтра
   не потрібен (фільтр для `strategy = ai` пропускається, щоби не платити двічі).
4. **Бюджет LLM спільний.** Виклики записуються в `llm_usage` з ціною, ліміти
   д/місяць з «Налаштування» діють так само (відхилення «Вичерпано бюджет LLM»).
5. **В бектесті AI не берує участі** — там лише детермінові стратегії.
6. **Ключі через Windows Credential Manager**, маскування секретів — як зараз.

## Потік даних

```
розклад (ET, конфіг) або кнопка в UI «Запустити аналіз»
  → refresh_market_data: бари юніверсу (як у вечірньому скан)
  → для кожного кандидата (визначений сканом, як пройшов якість даних)
      контекст: останні N барів, індикатори (ті самі, що для стратегій),
      новини за 7 днів (Finnhub), чи маємо позицію, календар звітів
  → Claude Messages API (fond-adapters::claude_strategist)
      → JSON-пропозиція: { symbol, action, stop, take_profit?, confidence,
        explanation, key_reasons[] }
  → верифікація (санітиз-чіки): стоп > 0, для купівлі стоп < ціна,
      тікер у юніверсі, не дублікат
  → ризик-менеджер (fond_core::risk::evaluate) → Intent (Entry/Exit)
      → «з підтвердженням» — екран «Схвалення»; «авто» — submit
  → події + ws + журнал
```

## Контракт пропозиції (Claude)

```
pub struct AiProposal {
    pub symbol: String,
    pub action: AiAction,        // Buy | Exit
    pub reference_price: f64,    // останній бізний close
    pub stop_price: f64,
    pub take_profit: Option<f64>,
    pub strength: f64,           // 0..1, впевненість
    pub explanation: String,     // українською
    pub key_reasons: Vec<String>,
}
```

- Системний промпт фіксований; всі вхідні дані — всередині `<context>` з defang'ом
  (як і в news-judge), щоб запобігти ін'єкції через заголовки новин.
- Відповідь строго за JSON-схемою (`output_config.format.json_schema`).
- Модель і effort — конфіг (замовчування: як для news-judge).

## Зміни по крейтах

| Крейт | Що |
| --- | --- |
| `fond-core` | `AiAction`, `AiProposal`; `StrategyId("ai")` |
| `fond-adapters` | `claude_strategist.rs` — запит/відповідь, парсинг, wiremock-тести |
| `fond-engine` | джоб `ai_review` у cycle; контекст-білдер (бари + індикатори + новини); верифікація; інтеграція з risk/submit; DTO |
| `fond-api` | `AiProposalDto`, події, REST: список пропозицій, «запустити аналіз» |
| `fond-store` | таблиця `ai_proposals` (at, symbol, action, payload, status, вердикт) |
| `apps/desktop` | екран «AI-аналіз»: кнопка «Запустити», список пропозицій (статус, причина, стоп/таргет, впевненість), кнопки «Схвалити / Відхилити» |

## Обмеження і безпечність

- **Макс. пропозицій за запуск** — конфіг (замовчування 5), щоб не вижечи бюджет.
- Один потік викликів LLM (rate-limiter з adapters, як у news-judge).
- Єдиний спосіб тестів: wiremock, без мережі.
- У межах budget=0 джоб пропускається з подією «пропущено: бюджет».

## Що не входить

- Портфельні цільові ваги і ребалансування — окрема частина 3.
- Бекетест AI-пропозицій — за принципом відсутній.
